# 数据与评估协议

## 数据划分

Spider 是跨数据库的 Text-to-SQL 数据集。本工程以 `db_id` 为完整分组，先读取官方训练来源，再将官方 dev 中的数据库按固定 seed 拆成验证和项目测试集合，检查三个集合的数据库互斥。

不能用“dev 一半”的行数来证明独立性：同一数据库的不同问题会共享 schema。新的数据库级划分不能强行维持原来的 517/517 数量，也不能与旧按行拆分的结果直接比较。

每次处理保存来源文件哈希、schema 数、样本数、数据库标识和 seed。样本 ID 使用稳定哈希，避免 Python 进程随机化影响对齐。小样本 smoke 输出标记其限额，独立于完整数据。

## 训练与选择

只监督完整 SQL completion，prompt 与 padding 的 label 为 `-100`。超过长度上限的完整样本过滤并统计，避免截断 JOIN 或 WHERE 后还当作有效训练目标。训练中的 checkpoint 选择依据验证 loss。

提示词、LoRA 配置、解码和修复次数在验证集选择。最终测试只在配置冻结后执行一次；同次评估保存初始输出与修复后的输出，用于比较固定修复规则的影响。测试集观察不能反过来成为调参依据。

## 指标定义

- **String Exact Match：** 比较经规范化后的预测 SQL 和标准 SQL 字符串；保留字符串字面量大小写。这不是 Spider 官方结构匹配。
- **Execution Accuracy：** 在同一个 SQLite 数据库执行预测与标准 SQL，对比结果。没有排序要求时比较保留重复值的行集合；标准 SQL 有 `ORDER BY` 时比较有序行。NULL 与文本、数值类型保留区别。单个数据库内容仍可能让语义错误的 SQL 偶然匹配，不等价于官方 test-suite 评估。
- **可执行率：** 只表示 SQL 执行成功；查询答案可能仍然错误。
- **修复：** 仅预测 SQL 执行失败时触发。标准 SQL/数据库异常是数据错误，不向模型提供标准答案的错误。缺少数据库的样本必须保留记录，不能悄悄从总体分母删除。

同时保存总样本数、各成功计数、修复调用次数、初始与最终结果和数据错误。准确率必须有对应分子与分母；修复后可执行不意味着修复后正确。

## 结果证据

训练效果记录需要同时保留：

1. 实际数据统计和冻结的划分文件。
2. 基座模型、adapter、训练配置、seed 和软件版本。
3. 训练状态和验证 loss 记录。
4. 逐条初始/最终预测、标准 SQL 与执行错误。
5. 由同一批逐条记录计算的 metrics JSON。

GitHub 可以提交评估报告与去标识的代表样例，模型权重通过适当的外部制品平台分发，Spider 数据遵循官方条款另行下载。人工示例和单元测试结果不能填入模型实验表。
